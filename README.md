## Краткое описание проекта

Построение сегментированной клиентской базы интернет-магазина для последующего использования групп (сегментов) пользователей в CRM-коммуникациях.

## Бизнес-задача

Необходимо разделить клиентскую базу на группы с разным уровнем вовлеченности, чтобы использовать для них разные сценарии маркетинговых коммуникаций.

Основная задача анализа - сформировать SQL-запрос, который для каждого клиента формирует профиль активности и определяет его сегмент (группу).

Сегментация должна учитывать не только наличие покупок, но и отсутствие покупательской активности у новых и давно зарегистрированных пользователей. Это позволит отделить потенциально лояльных клиентов от пользователей, которых имеет смысл реактивировать, и от недавно зарегистрированных клиентов, для которых ещё не было достаточно времени совершить покупку.

## Подход к решению задачи

Для каждого клиента были рассчитаны:

- количество доставленных заказов;
- количество событий покупки;
- среднее время доставки;
- количество дней с момента регистрации.

На основе количества доставленных заказов и давности регистрации клиенты были разделены на четыре сегмента.

## Данные

Для анализа используются три таблицы:

### `customers`

| Поле | Тип данных | Описание |
|---|---|---|
| `customer_id` | INT, Primary Key | Уникальный идентификатор клиента |
| `customer_city` | VARCHAR(100) | Город проживания клиента |
| `created_at` | TIMESTAMP | Дата и время регистрации клиента |

### `orders`

| Поле | Тип данных | Описание |
|---|---|---|
| `order_id` | INT, Primary Key | Уникальный идентификатор заказа |
| `customer_id` | INT, Foreign Key | Идентификатор клиента, совершившего заказ |
| `order_status` | VARCHAR(50) | Текущий статус заказа |
| `order_created_time` | TIMESTAMP | Дата и время создания заказа |
| `order_delivered_customer_time` | TIMESTAMP | Дата и время фактической доставки заказа клиенту; `NULL`, если заказ не был доставлен |

### `customer_actions`

| Поле | Тип данных | Описание |
|---|---|---|
| `customer_id` | INT, Foreign Key | Идентификатор клиента, совершившего действие |
| `event_timestamp` | TIMESTAMP | Дата и время события |
| `event_type` | VARCHAR(50) | Тип действия пользователя |
| `order_id` | INT | Идентификатор связанного заказа |
| `product_id` | INT | Идентификатор связанного товара |

Основной объект анализа — клиент. Поэтому итоговая выборка формируется на уровне `customer_id` и содержит одну строку на каждого клиента.

## Результаты

В результате для каждого клиента был сформирован маркетинговый сегмент: «Постоянный», «Разовый», «Неактивный» или «Новый».
